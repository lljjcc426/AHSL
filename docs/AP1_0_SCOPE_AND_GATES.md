# AP1.0 范围与门槛

## 唯一科学问题

AP1.0 只检验：当前强增量递归查询系统在现实变化数据上，是否存在可复现、跨工作负载且可归因于内部执行机制的“保留状态—更新/尾延迟”残差。它不是新算法阶段，也不比较综合排名。

冻结基线为 `f9ac16f418e34a5d130adeb332374493ff254332`，分支为 `project-ap1.0-recursive-state-latency-residual-gate`。P0、AP0 及更早阶段的结论未修改。

## 判定规则

候选残差至少满足一项材料性条件：保留状态或更新峰值内存恶化不低于 2 倍；p99 更新尾延迟恶化不低于 2 倍；可比较场景的内部更新工作不低于 2 倍；或出现可重复的超时/OOM 而精确对照仍可运行。

材料性只是必要条件。GO 还要求：

1. 每批精确结果正确；
2. 同一机制出现在至少两个不同递归类别；
3. 至少一个现实或可辩护的混合更新场景通过门槛；
4. 机制属于内部执行路径，且小型因果干预支持归因；
5. 最强现有系统和现有文献没有已直接解决该问题；
6. FlowLog 路线与 LDBC 更新路线均可用；
7. 问题可在一个现有引擎中形成聚焦的系统性修复。

## 实际结论

本轮所有 276 个原始行（230 个计量行）均 `exact_match=TRUE`。FlowLog 的同引擎增量模式在所有 11 个单元上均快于同引擎从头重算，速度比为 2.560–8.953 倍。最大增量/重算进程更新峰值 RSS 比为 1.969 倍，低于 2 倍门槛；内部维护状态、重推导和 arrangement 字节数不可得，因此不以 RSS 或输出变化数替代内部量。

部分单元的 `p99/p50` 超过 2，但这是增量模式自身的短序列离散度，不是“相对可比策略恶化”，且增量 p99 仍低于相应重算 p99。没有一个内部机制同时通过材料性、跨类别、现实场景和因果归因四道门。

因此主类为 `R7 NO ACTIONABLE RESIDUAL`，决定为 `AP1.0-C — NO-GO: MODERN SYSTEMS CLOSE THE RESIDUAL`。这里的含义限定为：在已成功执行的最强主系统 FlowLog 与本冻结矩阵中，没有足以授权 AP1.1 的残差；不外推为所有系统、所有规模上的普遍定理。

## 明确禁止与停止动作

本阶段没有实现新状态策略、调度器、传播算法、成本模型或新 IR，没有使用 ML/AI。由于 GO 条件不成立，不创建 `docs/AP1_1_CONCRETE_PROBLEM_PROPOSAL.md`，也不通过增加 GPU、分布式执行、更多数据集或语言来补救本方向。
