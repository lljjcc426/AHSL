# AP-R0 AI/ML collision audit

AI is optional in A/D/E solver execution and structurally necessary only for
semantic proposal tasks. The main collision is not a missing neural component;
it is that current benchmarks often bundle the scientific question with a
changing foundation-model baseline.

| Candidate | AI role | Stability test | Collision |
|---|---|---|---|
| A1 hybrid query execution | AI-N1 | query execution remains important with better models | learned routing is already crowded; core indexes are non-ML |
| B1 verified workflows | AI-N2 | verification/recovery remains important | verifier loops, retry, multi-agent and model switching are not novelty |
| C1 repository test generation | AI-N2 | executable tests remain meaningful | generation accuracy alone and another code model are saturated |
| D1 dynamic compilation | AI-N0/N1 | compiler problem is model-independent | generic ML autotuning/cost modeling is mature and unnecessary here |
| E1 constraint synthesis | AI-N2 | natural-language intent requires semantics | "LLM + solver" and self-verification already define the baseline |
| F1 fuzz repair | AI-N2 | repair verification remains important | larger model/more trajectories do not constitute the intervention |

No candidate receives credit for a hypothetical GNN, policy learner or larger
LLM. A future intervention would have to change execution/search/state or offer
a defensible specification/verifier contribution.
