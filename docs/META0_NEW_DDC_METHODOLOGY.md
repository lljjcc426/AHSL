# META0：Discovery → Development → Confirmation 方法学

日期：2026-08-28

## 1. 三阶段定义

### Discovery（发现）

一个方向进入 Development 只需同时满足：

1. 有真实或可信任务；
2. 有有意义且可执行的评价路径；
3. 有可证伪的技术机制；
4. 有可信正信号或已记录的结构化失败；
5. 方法、数据制度或实现仍有实质研究自由度。

Discovery 不要求已经形成完整论文，不要求跨域普适胜出、统一 2×/3× 效应、所有指标同时改善、两个独立 benchmark family、当前 SOTA 的完整复现或最终消融。

### Development（开发）

Development 是有预算的主动研究，而不是一次默认配置验证。允许在保留实验日志的前提下调整模型、损失、正则化、优化器、求解器配置、特征、实现与超参数；允许探索多个数据集和子制度。初始预算通常为 10–14 个工作日，并以开发结论 D-A/D-B/D-C/D-D 收束。

数据制度必须由机制先验描述，例如“高阶纯交互比例较高且复制噪声可估计”，不能事后定义成“本方法获胜的数据集”。

### Confirmation（确认）

只有方法和目标制度成熟后，才冻结：问题、方法、制度规则、主指标和 guardrail。随后使用当前强基线、公平调参、独立保留实例、适当重复运行与完整失败报告来确认出版主张。当前可执行强基线的材料性 residual 是 Confirmation 条件，不是进入 Development 的门票。

## 2. 失败类型

- **H：硬科学关闭。** H1 目标根本无效/不可达；H2 无新观测路线的不可识别；H3 问题与贡献均被近乎同题占据；H4 没有有意义可评价任务；H5 关键资源根本不可获得；H6 必然只是平凡集成。
- **F：精确表述关闭。** 该数学/协议表述失败，但其知识可迁移到更宽问题；不自动重开原表述。
- **S：软经验关闭。** 任意阈值未过、仅一域有信号、工程未跑通、默认参数未胜或当前强基线尚未复现；必须在 META0 重审。
- **O：开放/欠开发。** 任务与信号可信，但从未进行严肃方法开发。

H 与 F 可并存：例如 CertPath 的“正加性代价使自然真值可达”这一精确目标既是表述失败，也是 H1；外围的约束推理问题不随之消失。

## 3. 指标与效应规则

每个 Development 项目设一个 **primary metric** 和一组 **guardrail metrics**。科学判断基于 Pareto 权衡，而非所有指标普遍占优。效应大小按领域成熟度、运行方差、指标重要性、基线成熟度及实际价值解释；不再使用跨领域统一 2×/3× 阈值。

条件优势可以构成诚实主张：在可独立定义的条件 C 下，机制 M 导致基线失败 B，方法改善主指标 P，同时 guardrail 保持可接受。该主张在 Confirmation 前必须冻结 C。

## 4. 开发债

- **D0：** 已有严肃方法开发；
- **D1：** 小型原型或部分调参；
- **D2：** 几乎没有方法开发；
- **D3：** 仅文献/可行性审计。

D2/D3 加可信信号意味着“值得有界开发”，不等于“必然成功”。D0 也不自动表示关闭，仍须看硬科学条件。

## 5. 阶段转换

- Discovery → Development：五项 Discovery 条件成立，且 1–3 周开发杠杆可信。
- Development → Confirmation：出现重复可见的条件优势，机制证据与主指标一致，guardrail 可接受，并能在方法表现之外定义目标制度。
- Development → 停止：合理调参和多个机制不同的干预仍无可重复材料性改善，或出现新的 H 级事实。
- Confirmation → 主张冻结：只有在强基线、公平调参、保留数据和失败报告齐备后进行。

## 6. 本项目执行边界

META0 只做回顾、定向 prior-art 更新与研究管理校正；不训练新模型，不把旧结果伪装成新确认。META1 才启动唯一 Rank 1 的 Development。历史报告保持原样，它们记录当时的门槛和结论。
